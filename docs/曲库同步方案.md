# 曲库自动同步方案

## 使用方式

电脑为 Windows，继续使用 OneDrive 客户端。电脑播放器管理 OneDrive 本地同步目录中的曲库；手机播放器管理通过系统文件选择器授权给轻同步的曲库目录。轻同步负责把手机目录与同一个 OneDrive 曲库目录进行双向同步。电脑播放器的标签编辑、封面刮削和文件增删都会视为曲库变更。

现有单向任务保持原行为，不能直接将它们的上传记录当作双向共同基线。新曲库任务首次扫描必须完整列出两端文件；同路径同内容建立共同基线，仅一端存在则复制，两端同名不同内容则形成冲突。

## 比较与提交

以相对路径定位文件，以完整内容 SHA-256 比较版本。共同基线只在两端内容校验一致后推进；时间、大小、标签标题不能决定哪个版本更新。音乐之外的封面、歌词、播放列表等旁挂文件一并同步。

| 与共同基线相比 | 执行计划 |
|---|---|
| 两端未变 | 跳过 |
| 手机改、电脑未改 | 备份旧版后上传 |
| 电脑改、手机未改 | 备份旧版后下载 |
| 两端变成相同内容 | 验证后更新基线 |
| 两端改成不同内容 | 保留两份，展示冲突，不推进基线 |
| 一端删除，另一端未变 | 备份后传播删除，记录删除墓碑 |
| 一端删除，另一端修改 | 删除与修改冲突，保护修改版 |
| 两端删除 | 保留墓碑，避免当作首次同步 |

执行前再次检查云端 eTag 和本地内容，防止播放器在扫描后修改文件。下载先写入临时文件并校验，再替换目标；崩溃恢复必须根据持久操作日志完成或回退。完整目录扫描失败、授权失效、网络中断不能等同于文件删除。

## 版本与恢复

每个观察到的新版本、被覆盖版本和待删除版本先保存历史内容与清单，成功后才修改曲库。历史放在 OneDrive 曲库之外的独立目录，避免播放器把旧版本重复加入音乐库。使用内容哈希去重；默认不自动清理历史，容量不足时停止有风险的操作。

历史页面应展示原路径、版本时间、来源、内容哈希、大小和删除事件。恢复先展示目标差异；恢复当前文件之前同样备份当前版本。双方修改冲突可选择手机版、云端版或同时保留；选择前不静默覆盖。

Windows 的普通 OneDrive 客户端不理解轻同步清单。轻同步能保护它已观察和归档的版本；电脑在手机离线期间产生又消失的中间版本，需要 OneDrive 自身版本历史或电脑端组件保护，不能承诺无限历史或绝对不丢失。

## 改名与文件身份

先按新增与删除处理路径变更，只有唯一且相同哈希的新旧路径才可提示可能改名。多个同内容副本、改名同时修改、两端改到不同路径均不能自动猜测。首版不承诺跨播放器可靠追踪文件身份。

## 删除与发布验证

自动同步是已选定的产品方向。删除执行仍需要明确确认：先实现可查看的删除计划、备份及恢复，再请求启用删除传播。在获得确认前不删除真机或 OneDrive 文件。

发布前需要隔离测试目录验证两端新增、两端标签修改、封面修改、删除与修改冲突、单端删除、同名冲突、离线重连、失败重试、断电恢复及历史还原。

当前已接入曲库模式的三方比较、云端分页枚举、下载校验、手机与云端版本历史备份、单端增改传播、历史页面及恢复为副本。旧任务默认为单向，新任务可选择曲库模式，曲库模式需要重新选择手机目录授予持久读写权限。自动删除尚未执行，只在同步结果中报告待确认路径；冲突不会自动选择赢家。历史 `.bin` 内容与对应 JSON 清单位于 `轻同步历史/<任务ID>`。

当前使用安卓文件提供方的写入接口替换已备份文件；尚无跨进程操作日志和原子替换保证。写入中断可能留下不完整的手机当前文件，已有版本仍可从历史恢复为副本。大曲库性能、真机双向流程及故障恢复尚需验证；不得把当前实现描述为已验证的完整 Git 式曲库系统。
