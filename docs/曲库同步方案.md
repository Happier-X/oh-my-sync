# 曲库自动同步方案

## 使用方式

电脑为 Windows，继续使用 OneDrive 客户端。电脑播放器管理 OneDrive 本地同步目录中的曲库；手机播放器管理通过系统文件选择器授权给轻同步的曲库目录。轻同步负责把手机目录与同一个 OneDrive 曲库目录进行双向同步。电脑播放器的标签编辑、封面刮削和文件增删都会视为曲库变更。

现有单向任务保持原行为，不能直接将它们的上传记录当作双向共同基线。新曲库任务首次扫描必须完整列出两端文件；同路径同内容建立共同基线，仅一端存在则复制，两端同名不同内容则形成冲突。

## 比较与提交

以相对路径定位文件，以完整内容 SHA-256 比较版本。共同基线只在两端内容校验一致后推进；时间、大小、标签标题不能决定哪个版本更新。音乐之外的封面、歌词、播放列表等旁挂文件一并同步。

| 与共同基线相比 | 执行计划 |
|---|---|
| 两端未变 | 跳过 |
| 手机改、电脑未改 | 备份旧版后上传 |
| 电脑改、手机未改 | 备份旧版后下载 |
| 两端变成相同内容 | 验证后更新基线 |
| 两端改成不同内容 | 保留两份，展示冲突，不推进基线 |
| 一端删除，另一端未变 | 备份后传播删除，记录删除墓碑 |
| 一端删除，另一端修改 | 删除与修改冲突，保护修改版 |
| 两端删除 | 保留墓碑，避免当作首次同步 |

执行前再次检查云端 eTag 和本地内容，防止播放器在扫描后修改文件。下载先写入临时文件并校验，再替换目标；崩溃恢复必须根据持久操作日志完成或回退。完整目录扫描失败、授权失效、网络中断不能等同于文件删除。

## 版本与恢复

每个观察到的新版本、被覆盖版本和待删除版本先保存历史内容与清单，成功后才修改曲库。历史放在 OneDrive 曲库之外的独立目录，避免播放器把旧版本重复加入音乐库。使用内容哈希去重；默认不自动清理历史，容量不足时停止有风险的操作。

历史页面应展示原路径、版本时间、来源、内容哈希、大小和删除事件。恢复先展示目标差异；恢复当前文件之前同样备份当前版本。双方修改冲突可选择手机版、云端版或同时保留；选择前不静默覆盖。

Windows 的普通 OneDrive 客户端不理解轻同步清单。轻同步能保护它已观察和归档的版本；电脑在手机离线期间产生又消失的中间版本，需要 OneDrive 自身版本历史或电脑端组件保护，不能承诺无限历史或绝对不丢失。

## 改名与文件身份

先按新增与删除处理路径变更，只有唯一且相同哈希的新旧路径才可提示可能改名。多个同内容副本、改名同时修改、两端改到不同路径均不能自动猜测。首版不承诺跨播放器可靠追踪文件身份。

## 删除与发布验证

自动同步是已选定的产品方向。删除传播默认关闭，用户必须在任务设置中确认启用。候选先展示，再经过两次完整扫描且间隔至少一分钟核对。默认只处理相对共同基线未改的另一端版本，先存历史再移出有效曲库；不执行永久删除。

发布前需要隔离测试目录验证两端新增、两端标签修改、封面修改、删除与修改冲突、单端删除、同名冲突、离线重连、失败重试、断电恢复及历史还原。

当前已接入曲库模式的三方比较、云端分页枚举、下载校验、手机与云端版本历史备份、单端增改传播、历史页面及恢复为副本。旧任务默认为单向，新任务可选择曲库模式，曲库模式需要重新选择手机目录授予持久读写权限。冲突不会自动选择赢家。历史 `.bin` 内容与对应 JSON 清单位于 `轻同步历史/<任务ID>`。

0.0.1 正式版在修改前把路径、旧新哈希、云端身份与版本、临时名及副本名写入 DataStore。下载内容同时持久保存在应用私有历史中。手机先写临时文件并读回校验，再改名保留原文件、将新文件改名成原名；完成日志与共同基线在同一次 DataStore 更新中提交。重新运行先检查目标、临时副本和旧版的实际内容，完成未结束的步骤，遇到外部改动停止。历史恢复副本复用同一流程。

上传响应丢失时，根据原位置的新内容哈希识别已经完成的提交；不强制覆盖新的未知内容。云端删除传播使用带 `If-Match` 的 [Graph 移动接口](https://learn.microsoft.com/en-us/graph/api/driveitem-move?view=graph-rest-1.0)，将原项目移入独立历史目录；响应丢失时按项目 ID 与内容核对移动目的地。手机删除传播采用同目录唯一隐藏名隔离，隔离副本和替换旧版按文件身份及相对路径排除扫描。

手机目录使用直接文档查询，查询失败不当作空目录。云端已建立基线的曲库根缺失时停止，不重建根后猜测删除。批量缺失至少 10 个文件且超过已知路径四分之一时停止自动传播。删除候选、隔离操作与未完成日志均显示在历史页。

同目录两次改名不是一个原子操作，文件提供方不支持改名时保留原版、临时副本及日志并停止。日志保证应用进程中断后可核对重放，不能保证所有存储提供方在断电时的持久性。隔离副本、历史和下载缓存默认不清理，播放器是否忽略隐藏副本取决于其扫描规则。大曲库性能、厂商文件提供方及真实 OneDrive 双向故障恢复仍需验证；不能承诺完整 Git 式无限历史或绝对不丢失。
